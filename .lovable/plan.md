# اصلاح کامل انتشار Cloudflare، ورود پیشخوان، تصاویر و هوش مصنوعی

## نتیجه بررسی
- فایل Wrangler در زمان Build تولید می‌شود و نام Worker فعلاً ثابت نشده است؛ بنابراین ممکن است Secretها روی یک Worker تنظیم و کد روی Worker دیگری منتشر شود.
- Workflow فقط متغیرهای Build را می‌فرستد و Secretهای زمان اجرا را نصب یا اعتبارسنجی نمی‌کند. در کد هیچ نگاشت Secret خالی یا با نام `_` وجود ندارد؛ `_` احتمالاً در تنظیمات فعلی Cloudflare ایجاد شده و باید یک‌بار از آنجا حذف شود.
- رمز ورود فقط از `DASHBOARD_PASSWORD` خوانده می‌شود، اما نشست امن به `SESSION_SECRET` جداگانه و حداقل ۳۲ کاراکتری نیاز دارد. نبودن یا کوتاه بودن آن باعث خطای 500 و گیرکردن فرم ورود می‌شود.
- بخشی از تصاویر به دامنه `si8452.ir` و لوگوی GIF به مسیر اختصاصی `/__l5e/...` وابسته است؛ این مسیرها در Cloudflare قابل اتکا نیستند.
- API هوش مصنوعی به `LOVABLE_API_KEY` در محیط Runtime همان Worker نیاز دارد؛ وجود کلید در Lovable به‌تنهایی آن را به Cloudflare منتقل نمی‌کند.
- تصاویر آپلودشده و عملیات مدیریتی فعلی به دسترسی سروری پایگاه داده نیاز دارند؛ نبود تنظیمات Runtime آن‌ها را از کار می‌اندازد.

## تغییرات کد
1. نام Worker را به‌صورت ثابت در تنظیمات Build تعیین می‌کنم تا هر انتشار دقیقاً روی همان Worker دارای Secretها انجام شود.
2. Workflow را اصلاح می‌کنم تا:
   - فقط نام‌های صریح و معتبر Secret را بپذیرد و هر مقدار خالی را پیش از Deploy متوقف کند؛
   - هیچ Secret با نام خالی یا `_` نسازد؛
   - Secretهای Runtime لازم را با نام‌های ثابت روی همان Worker ثبت کند؛
   - سپس Deploy و یک Health Check برای ورود، تصویر و AI انجام دهد.
3. ورود پیشخوان را مقاوم می‌کنم:
   - `DASHBOARD_PASSWORD` تنها متغیر رمز ورود باقی می‌ماند؛
   - `SESSION_SECRET` فقط برای رمزنگاری نشست استفاده می‌شود و اعتبارسنجی واضح ۳۲+ کاراکتری دارد؛
   - خطای «تنظیم‌نشده»، خطای نشست و رمز اشتباه در UI از هم تفکیک می‌شوند و فرم دیگر روی Loading/Busy گیر نمی‌کند.
4. فایل GIF را به دارایی واقعی داخل پروژه تبدیل می‌کنم و تمام مسیرهای `/__l5e/...` را حذف می‌کنم.
5. لوگوها و پس‌زمینه‌های وابسته به `si8452.ir` را با فایل‌های محلی پروژه جایگزین می‌کنم تا Cloudflare همیشه آن‌ها را ارائه کند.
6. مسیر عمومی تصاویر آپلودشده را با پاسخ خطای قابل‌تشخیص و Cache مناسب مقاوم می‌کنم؛ خطای تنظیمات Backend دیگر به‌صورت 404 مبهم دیده نمی‌شود.
7. API هوش مصنوعی را با پاسخ‌های تشخیصی امن برای نبود کلید/تنظیمات Runtime اصلاح می‌کنم و Workflow وجود تنظیمات لازم را قبل از Deploy کنترل می‌کند.
8. فهرست متغیرهای پنل انتشار و راهنمای Cloudflare را با واقعیت کد همسان می‌کنم و دستور حذف دستی Secret نامعتبر `_` را دقیق ثبت می‌کنم.

## نکته امنیتی
`DASHBOARD_PASSWORD` و `SESSION_SECRET` نباید یکی باشند: اولی رمز تایپی مدیر است و دومی کلید داخلی رمزنگاری Cookie. حذف `SESSION_SECRET` یا استفاده مجدد از رمز مدیریت، امنیت نشست را کاهش می‌دهد.

## اعتبارسنجی
- Build خودکار پروژه و بررسی Wrangler تولیدشده برای نام Worker و نبود نگاشت خالی.
- تست ورود با وضعیت‌های رمز درست، رمز نادرست، Secret نشست نامعتبر و حفظ نشست پس از Refresh.
- بررسی همه درخواست‌های تصویر برای نبود 404 و حذف کامل وابستگی‌های `/__l5e/` و `si8452.ir`.
- تست پاسخ API هوش مصنوعی و پیام تشخیصی صحیح در نبود تنظیمات.
- بررسی مسیرهای عمومی اصلی و صفحات بیمه در نمای دسکتاپ و موبایل.

## اقدام لازم پس از ادغام کد
در GitHub Actions باید مقادیر Runtime با همین نام‌ها موجود باشند: `DASHBOARD_PASSWORD`، `SESSION_SECRET`، `LOVABLE_API_KEY` و تنظیمات Backend موردنیاز. Secret نامعتبر `_` نیز باید یک‌بار از Worker فعلی Cloudflare حذف شود؛ Workflow اصلاح‌شده دیگر آن را ایجاد نخواهد کرد.
